## Deployment
1. Create R2 bucket `moksha-reel-v5-private-media` in the primary account; keep public access disabled.
2. Deploy `worker.mjs` as Worker `moksha-reel-v5-media-vault` with R2 binding `MEDIA` pointing to that bucket.
3. Configure strong random independent Worker secrets `VAULT_TOKEN` and `SIGNING_KEY` via Cloudflare secret API or Wrangler. Never commit them.
4. Confirm `GET /health` returns `ready:true`. Use authenticated `PUT /objects/source/1000083489.mp4` with `Authorization: Bearer <VAULT_TOKEN>` and `Content-Type: video/mp4`. Verify checksum after download. Worker single-request upload is constrained by Cloudflare plan request body limits; add multipart R2 uploads for larger videos.
5. GitHub runner uses `GET /objects/source/1000083489.mp4` with the bearer secret, or an expiring signed URL generated by `POST /sign`. For finished render upload to `render/<job-id>.mp4`; request signed GET for browser playback with byte-range support.
6. Never expose the bearer token in preview URLs, GitHub logs, or repository contents. Signed URLs expire within 3600 seconds; treat links as bearer capabilities. Rotate compromised secrets. Avoid uploading sensitive guest footage without clearance.
7. Validate HEAD/GET, byte ranges, expiry, invalid signatures, unauthorized PUT, integrity, codec and actual playback. Preserve owner publishing approval.
