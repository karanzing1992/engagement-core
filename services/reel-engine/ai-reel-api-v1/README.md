## Phase 1 real-video editor extension (2026-11-04, owner-only)
This section supersedes the earlier *synthetic-only* Phase 1 description after owner scope correction. The old synthetic workflow remains independently protected.

**Private intake:** Dedicated Cloudflare Workers KV namespace `delulutech-mad-v1-private-media` (R2 is disabled in this account). Maximum 80 MiB one source file, MP4/MOV/WebM; uploaded in ≤4 MiB SHA256-verified chunks (48h TTL); D1 chunk receipts and one active render database constraint. Current free KV limits: 1GB storage, 1,000 writes/day; not for public multi-user service.

**User UI:** Branded NextChat at https://reel.delulutech.in, **AI Reel Engine 1.0 — Upload & Edit Real Video** above composer. Set the owner code in Settings, choose real footage, enter a cinematic brief, explicitly confirm source edit rights, consent for recognizable people, and Gemini/Groq external-processing permission. The PWA locally hashes the file, sends verified chunks, finalizes, then creates a D1 job. Use Check status and Get Private Preview. Preview fetch uses the owner code and produces a local object URL and downloadable MP4; no anonymous media URLs.

**Render:** Existing GitHub Actions workflow `.github/workflows/mad-v5-cloudflare-bridge.yml`, authenticated with pinned GitHub OIDC claims, leases one owner media job independently of the synthetic queue. Reads raw video only from private Workers KV via authenticated bounded chunks, validates complete SHA256 and actual FFprobe source, samples actual frames for Gemini when available/consented, requests a V5 Groq director plan when available, compiles grounded source cuts, applies the FFmpeg multi_renderer transitions/audio normalization, overlays a text hook, verifies full H.264/AAC 1080×1920 output, pushes private output chunks back to KV, and writes `PRIVATE_REAL_MEDIA_TECHNICAL_DRAFT` receipt to D1. The GitHub runner is ephemeral and **real video is never uploaded to GitHub Actions artifacts or issue bodies**.

**Fallback fidelity:** If vision/Groq planning fails, source-derived cuts are rendered without inventing source visuals and the receipt records `source_only_fallback`; do not market a fallback as a complete AI-directed cinematic edit. Existing source audio can be used if authorized; third-party music selection/licensing and final sound-sync artistic acceptance remain separate **owner QA gates**. No external soundtrack with unverifiable rights is added. Job pickup uses the existing scheduled GitHub workflow; queue ETA belongs in Phase 2.

**Endpoints:** authenticated POST `/v1/media/uploads`, PUT `/v1/media/uploads/{upload_id}/chunks/{index}`, POST `/v1/media/uploads/{upload_id}/complete`, POST `/v1/media/jobs`, GET `/v1/media/jobs/{job_id}`, GET `/v1/media/jobs/{job_id}/preview`, GET `/v1/media/jobs/{job_id}/receipt`. Pinned signed GitHub workload endpoints are `/bridge/v1/media-claim`, `/bridge/v1/media-source/{job_id}/{index}`, `/bridge/v1/media-output/{job_id}/{index}`, and `/bridge/v1/media-complete`. No public tools, MPC/MCP client, unrestricted cross-tenant use or publication.

**Schema:** `002_media.sql` + `003_chunks.sql`. **Isolation:** keep existing single-owner hash secret, strict browser Origin policy and GitHub OIDC JWT pins. Never log keys or put guest media in public GitHub files. **Rollback:** remove only appended private media route and additional media workflow steps, preserve unrelated synthetic bridge. Automatic KV data expiry is not an immediate purge guarantee for backups.

**Phase 1 acceptance is not public certification.** Owner shall submit real permission-cleared source, review preview, verify creative cut/caption/music expectations and separately approve publication. Phase 2 multi-user queues, Phase 3 creative prompt suggestions remain documented-only.
